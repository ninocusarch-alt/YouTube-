# Windows EXE 启动器设计规范

## 1. 目标

把当前需要在 PowerShell 中手动执行的 FastAPI 启动流程，改造成电脑小白可以双击运行的 Windows 程序。

目标体验：

```text
电脑开机
  → 双击 VideoCompanionBackend.exe
  → 窗口显示“服务已就绪”
  → 打开 YouTube 并点击 Chrome 插件
  → 直接使用实时双语理解与视频问答
```

当前阶段不实现开机自启、不迁移云端，也不让 Chrome 插件直接启动本地程序。

## 2. 方案选择

采用 **PyInstaller onedir 文件夹版 + Tkinter 可视化启动器**。

选择理由：

- `onedir` 无需每次启动时解压整个 Python 运行环境，启动速度和稳定性优于单文件模式；
- FastAPI、Uvicorn、WebSocket、Pydantic 等依赖较多，文件夹版更容易排查漏包；
- Tkinter 随 Python 提供，不额外引入大型 GUI 框架；
- 用户实际只需双击一个 EXE，不要求交付物必须只有一个物理文件；
- 后端仍监听 `127.0.0.1:8000`，现有 Chrome 插件协议无需重构。

不采用：

- PyInstaller onefile：启动时临时解压，速度更慢且更容易触发杀毒软件误报；
- Native Messaging：安装和注册流程复杂，当前只是启动本地服务，不需要让插件控制本地进程；
- 云端后端：会引入服务器费用、鉴权、密钥托管和数据合规问题。

## 3. 用户界面

启动器使用一个简洁的 Windows 窗口，包含：

- 产品名称：Real-time AI Video Companion；
- 状态指示：未启动、正在启动、服务已就绪、配置缺失、端口冲突、启动失败；
- 后端地址：`http://127.0.0.1:8000`；
- “启动服务”按钮；
- “停止服务”按钮；
- “重新启动”按钮；
- “打开健康检查”按钮；
- “配置 API Key”按钮；
- 只显示必要信息的日志区域。

窗口可以最小化。用户关闭窗口时，如果服务仍在运行，应弹出确认：关闭启动器会同时停止本地后端，Chrome 插件将暂时无法使用。

## 4. 首次运行与密钥配置

### 4.1 配置位置

运行配置保存在启动器文件夹旁的 `.env`：

```text
VideoCompanionBackend/
  VideoCompanionBackend.exe
  .env
  .env.example
  _internal/
```

启动器必须按 EXE 所在目录解析 `.env`，不能依赖用户从哪个文件夹双击或当前工作目录。

### 4.2 首次运行

如果 `.env` 不存在：

1. 从随包提供的 `.env.example` 创建本地 `.env`；
2. 打开 API Key 配置对话框；
3. 用户粘贴 `DASHSCOPE_API_KEY`；
4. 保存后重新读取配置并执行健康检查；
5. Key 为空时不启动服务，并给出可理解的提示。

### 4.3 安全要求

- 不把真实 Key 编译进 EXE；
- 不在日志和错误弹窗中显示完整 Key；
- `.env` 继续被 Git 忽略；
- 发布包只包含 `.env.example`；
- 用户修改 Key 时使用原子替换，避免写出半个配置文件；
- 文档提醒用户不要截图或分享 `.env`。

## 5. 进程与服务生命周期

### 5.1 启动方式

启动器在后台线程中运行 Uvicorn，加载现有的 `app.main:app`，监听：

```text
host = 127.0.0.1
port = 8000
```

GUI 主线程不得被 Uvicorn 阻塞。

### 5.2 就绪判断

点击启动后：

1. 检查 `.env` 和 `DASHSCOPE_API_KEY`；
2. 检查 8000 端口；
3. 启动 Uvicorn；
4. 轮询 `GET /api/health`；
5. 只有健康接口返回 `ok=true` 且 ASR、翻译均已配置时，状态才变为“服务已就绪”。

健康检查成功只代表本地服务和配置已读取，不代表千问实时 ASR 一定可联网。真正的千问握手仍发生在用户点击插件开始会话时。

### 5.3 停止与重启

- “停止服务”应请求 Uvicorn 正常退出并等待线程结束；
- “重新启动”必须先完成停止，再重新读取 `.env` 并启动；
- 关闭窗口时执行同样的正常停止流程；
- 不允许残留占用 8000 端口的子进程。

### 5.4 重复启动

启动器启动时先访问 `/api/health`：

- 如果返回本项目的健康响应，显示“服务已经运行”，不再启动第二个实例；
- 如果端口可连接但不是本项目响应，显示“8000 端口被其他程序占用”；
- 如果端口未占用，允许启动服务。

## 6. 错误处理

| 场景 | 用户提示 | 可执行动作 |
|---|---|---|
| 未配置 API Key | 尚未配置千问 API Key | 打开配置窗口 |
| 8000 端口被本项目占用 | 服务已经运行 | 打开健康检查或继续使用插件 |
| 8000 端口被其他程序占用 | 端口被其他程序占用 | 显示检查建议，不强制结束其他进程 |
| 后端启动失败 | 服务启动失败 | 展示简化错误，允许查看日志和重试 |
| 健康检查超时 | 后端未能在规定时间内就绪 | 停止残留服务并允许重新启动 |
| 千问会话连接失败 | 网络、Key 或模型权限可能异常 | 引导检查网络、Key、模型和地域端点 |
| EXE 被重复双击 | 已有实例正在运行 | 激活已有窗口，不创建第二个实例 |

不得自动结束未知进程，也不得在错误信息中暴露密钥。

## 7. 代码与产物结构

计划新增：

```text
backend/
  launcher/
    __init__.py
    main.py                Tkinter 窗口和用户操作
    server_controller.py   Uvicorn 生命周期和健康检查
    config_store.py        EXE 路径解析与 .env 安全写入
    single_instance.py     防止启动多个实例
  video_companion.spec     PyInstaller 配置
  launcher_requirements.txt
  build_launcher.ps1       开发者构建脚本

release/
  VideoCompanionBackend/
    VideoCompanionBackend.exe
    .env.example
    _internal/
```

`release/` 是本地构建产物。是否纳入 Git 由后续发布策略决定，默认不提交大型二进制文件。

## 8. 对现有系统的影响

### 保持不变

- Chrome 插件继续连接 `http://127.0.0.1:8000`；
- WebSocket 路径和消息协议不变；
- FastAPI 路由、Agent、断句器和 SessionStore 不变；
- `.env` 中现有千问配置继续生效。

### 需要调整

- 后端配置路径需要支持“源码运行”和“EXE 运行”两种根目录；
- 增加可由启动器控制的 Uvicorn 启停接口；
- 增加启动器专用的状态与错误映射；
- README 增加普通用户 EXE 使用说明，PowerShell 说明保留给开发者。

## 9. 测试策略

### 单元测试

- EXE 目录和源码目录的配置路径解析；
- `.env` 不存在、Key 为空和保存成功；
- 端口空闲、本项目已运行和未知程序占用；
- 状态机的启动、就绪、失败、停止和重启；
- 日志与错误提示不包含完整 API Key。

### 集成测试

- 启动器拉起 FastAPI 后 `/api/health` 正常；
- 停止后 8000 端口释放；
- 重复启动不会出现第二个服务；
- 修改 `.env` 后重启能够读取新配置；
- Chrome 插件可以连接 EXE 启动的后端并收到 `session.ready`。

### 打包验收

- 在没有安装 Python 的 Windows 电脑上双击可运行；
- 不出现 PowerShell 或命令提示符窗口；
- 首次运行可完成 Key 配置；
- 正常启动、最小化、恢复和退出；
- 关闭后不残留进程和端口；
- 构建包中不包含真实 `.env` 或 API Key。

## 10. 完成标准

- 用户每次开机只需双击 `VideoCompanionBackend.exe`；
- 窗口明确显示后端是否可供插件使用；
- 用户无需安装 Python、打开 PowerShell 或输入命令；
- 首次配置 Key 后，后续启动不再重复配置；
- 插件现有功能和协议保持兼容；
- 重复启动、端口冲突、配置缺失和启动失败均有可理解的处理；
- 后端及新增启动器测试通过，生产 EXE 在干净 Windows 环境完成验收。
